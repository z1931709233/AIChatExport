# 千问聊天导出工具使用说明

## 1. 文件说明

SVN 中只需要保存以下两个文件：

```text
chat-export.v2.user.js
千问聊天导出工具-使用说明.md
```

`chat-export.v2.user.js` 是可直接安装到 Tampermonkey 的成品脚本。同一个脚本同时支持腾讯元宝和千问，不需要上传项目源代码、测试文件或构建工具。

## 2. 运行条件

- Windows 10/11。
- 最新版 Google Chrome 或 Microsoft Edge。
- 浏览器已安装 Tampermonkey（篡改猴）扩展。
- 已在浏览器中正常登录千问网页版。
- 使用地址：<https://www.qianwen.com/>。
- “全部会话”导出依赖浏览器的文件夹写入功能，因此建议使用 Chrome 或 Edge。

## 3. 安装脚本

1. 打开 Tampermonkey 管理面板。
2. 选择“添加新脚本”。
3. 删除编辑器中的默认内容。
4. 打开 `chat-export.v2.user.js`，复制全部内容并粘贴到编辑器。
5. 保存脚本，并确认脚本处于启用状态。
6. 关闭已经打开的千问标签页，再重新打开千问网页。
7. 页面加载完成后，右下角会出现聊天导出按钮。

更新版本时，请用新版 `chat-export.v2.user.js` 完整覆盖 Tampermonkey 中原来的脚本。保存后关闭旧的千问标签页并重新打开，避免旧代码仍在页面中运行。脚本头部版本应为 `0.7.0` 或更高版本。

## 4. 导出当前会话

1. 在千问中打开需要导出的具体对话，确认地址类似：

   ```text
   https://www.qianwen.com/chat/<sessionId>
   ```

2. 点击页面右下角的导出按钮。
3. 选择“当前会话”。
4. 选择 JSON 或 Markdown 格式。
5. 点击“导出”。
6. 浏览器会按照当前下载设置保存文件。

当前会话导出以地址栏中的 `sessionId` 为准，不会从缓存中随意选择其他对话。

## 5. 导出全部会话

1. 登录千问，并进入任意正常聊天页面。
2. 等待左侧最近对话列表正常显示。
3. 点击页面右下角的导出按钮。
4. 选择“全部会话”。
5. 点击“导出”。
6. 浏览器弹出目录选择窗口后，选择用于保存备份的总目录，例如：

   ```text
   D:\ChatHistory
   ```

7. 授权网页写入该目录。
8. 保持千问标签页和浏览器打开，等待进度显示完成。

全部导出会自动处理：

- 账号历史会话列表的 `next_token` 分页；
- 单个长对话的详情分页；
- 重复轮次和消息去重；
- 按位置和时间恢复阅读顺序；
- 请求节流、有限重试和失败后继续；
- 本地缓存和中断后的续传；
- 每个成功会话立即写入本地目录。

单个会话最终失败不会终止其他会话，也不会删除已经写入的文件。获取和写入进度会显示在导出面板中。

## 6. 导出目录结构

用户选择的目录就是总目录，不会生成 ZIP。每个会话会创建一个独立子目录：

```text
<会话ID>_<时间>_<分组名>
```

示例：

```text
D:\ChatHistory\
├─ 63dcc7f165724efe8c489f65846d0ec1_20260830-120200_其他\
│  ├─ raw.json
│  └─ conversation.md
├─ 64849715bf6e467b9aba88849930505c_20260829-184500_其他\
│  ├─ raw.json
│  └─ conversation.md
└─ metadata.json
```

命名规则：

- 第一部分是完整会话 ID；
- 第二部分是会话时间，格式为 `年月日-时分秒`；
- 第三部分是分组名称；
- 当前列表没有提供分组名称时使用“其他”；
- Windows 非法字符会被自动替换；
- 同名目录自动追加 `_2`、`_3`，不会覆盖本次导出的其他会话。

文件用途：

- `raw.json`：以千问接口数据为主的 JSON 备份，保留轮次、原始消息、搜索/工具信息、模型信息和附件元数据；
- `conversation.md`：便于直接阅读的 Markdown 对话；
- `metadata.json`：本次导出的总清单、成功/失败数量以及缓存使用情况。

## 7. 原始数据与安全脱敏

千问详情响应可能在每个轮次中回显请求头、账号/设备标识、IP、Cookie、授权信息或签名。这些字段不属于对话正文，也不适合长期保存在备份中。

写入 `raw.json` 前，脚本会将以下明显凭据字段替换为脱敏标记：

```text
header / headers
cookie / authorization
access_token / refresh_token
client_ip / user_ip / ip
device_id
signature / sign
```

对话正文、用户问题、AI 回答、搜索结果、工具数据、模型名称和附件元数据仍会保留。即使经过脱敏，聊天记录仍可能包含用户主动输入的私人信息，因此不要随意公开或上传导出目录。

## 8. 缓存、断点续传与强制下载

脚本会把成功下载的会话保存在千问网站对应的浏览器本地存储中。浏览器关闭、页面刷新或导出中断后，再次执行“全部会话”可以复用符合条件的缓存，并继续处理剩余会话。

注意：

- 不要清除千问网站的 IndexedDB、Local Storage、Cookie 或站点数据，否则登录态和断点缓存可能丢失。
- 每次全量导出仍会重新读取服务器历史列表，以发现新增或更新的会话。
- 如果列表更新时间没有变化，脚本会优先复用完整缓存。
- 如需忽略缓存并强制重新下载全部详情，可在千问页面控制台执行：

  ```javascript
  getToolkit().exportAllConversations('directory', { forceFullExport: true })
  ```

执行后仍需在浏览器弹窗中手动选择目标文件夹。

## 9. 使用期间注意事项

- 导出过程中不要关闭千问标签页或退出浏览器。
- 不要同时在多个千问标签页启动全量导出。
- 脚本会故意限制请求速度，历史较多或对话较长时需要等待。
- 浏览器必须保持登录状态；登录失效、网络中断、限流或接口更新可能造成部分失败。
- 如果 `F12` 无法打开开发者工具，可右键页面选择“检查”，或按 `Ctrl+Shift+I`。
- 网页脚本只能写入用户在浏览器弹窗中明确选择并授权的目录，不能绕过浏览器权限直接写入任意路径。

## 10. 常见问题

### 10.1 页面没有显示导出按钮

确认 Tampermonkey 已启用脚本，并确认脚本匹配：

```text
qianwen.com
*.qianwen.com
```

然后关闭旧标签页，重新打开 <https://www.qianwen.com/>。还应确认没有同时启用两个版本的 Chat Export Toolkit。

### 10.2 导出提示请求失败或 HTTP 400/401/403

先确认千问网页本身可以正常打开对话，并且登录没有过期。刷新千问页面，等待左侧历史列表出现后再导出。脚本会从网页已经发出的千问 API 请求中取得当前登录会话所需的动态公共参数，因此页面刚打开时应先等待初始化完成。

### 10.3 全部导出缺少部分记录

打开目标目录中的 `metadata.json`，重点检查：

- `listedCount`：服务器列表中发现的会话数；
- `exportedCount`：实际成功写入的会话数；
- `failureCount`：详情请求或处理失败数量；
- `failures`：失败的会话 ID 和错误；
- `normalizationFailures`：Markdown 转换或文件写入失败。

保留 `metadata.json` 和浏览器控制台中的 `[QwenAdapter]` 错误，再提供给维护者排查。不要提供 Cookie、Token、完整请求头或未脱敏的 HAR 文件。

### 10.4 为什么文件夹分组名都是“其他”

当前已确认的千问历史列表接口主要返回会话 ID、标题和创建/更新时间，尚未完成独立分组列表的可靠接入。当列表项没有可用分组名称时，脚本按统一命名规则写为“其他”。这不影响会话正文和 JSON/Markdown 的导出。

### 10.5 Lint 未执行成功是否影响使用

不影响。当前仓库的 `lint` 命令缺少 ESLint 依赖和配置，因此无法启动代码风格检查；这不是导出代码报告了 lint 错误。TypeScript 类型检查、自动测试和生产构建均已通过。

## 11. 接口工作流程

千问全量导出的当前流程为：

```text
POST /api/v2/session/page/list
  请求：limit=50、sort_field=modifiedTime、next_token
  响应：data.list、data.have_next_page、data.next_token
        ↓
按 session_id 合并、去重
        ↓
GET /api/v1/session/msg/list
  请求：session_id、page、page_size、pos
  响应：data.list、have_next_page
        ↓
合并轮次、去重、恢复时间顺序
        ↓
本地缓存 → raw.json + conversation.md → metadata.json
```

分页过程中如果 `next_token` 或详情游标不再变化，脚本会停止并报告错误，避免无限请求。

## 13. 当前范围与限制

- “全部会话”当前指 `/api/v2/session/page/list` 在当前登录账号下返回的历史会话。
- 单独的千问“分组”接口尚未接入，因此当前目录中的分组名通常为“其他”。
- 千问网页版接口可能更新，接口变化后脚本可能需要同步维护。
- 新版 `response_messages` 和旧版 `qwen_response_messages` 均已兼容；特殊的新消息类型仍可能需要后续补充 Markdown 展示规则。
- 自动测试使用模拟请求，不依赖真实千问账号；最终效果仍受真实账号权限、网络、限流和千问服务状态影响。
